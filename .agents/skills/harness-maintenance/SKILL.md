# Harness Maintenance

Use [the harness improvement workflow](../../workflows/harness-improvement.md).
Map the finding to the smallest correct artifact and its governing numbered spec.
Preserve the docs-only boundary and accurate evidence. Reuse public engineering
procedures without copying another application's context, specs or decisions.

Run regression fixtures when changing enforcement. Reject false completion and
missing references without rewriting old evidence to pass a checker. Add only
integrations that perform a real, tested task in the chosen development tool.

Skill changes are repository source: review and synchronize them through the
same Git change as their spec. These are local project procedures, not personal
skill installations. No external personal-skill account is changed.

Completion: deterministic checks and the relevant quality gates pass, routing is
current, and the score report explains both improvements and detector limits.
